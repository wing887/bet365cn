## 一、产品概述

一个纯移动端H5模拟足球竞猜网站，严格模仿 Bet365 整站设计风格与交互模式。用户使用虚拟金币进行模拟下注，比赛结束后由系统自动获取比分、超管确认结算。

**版本规划**：
| 版本 | 内容 | 玩法 |
|------|------|------|
| V1.0 | 赛前下注 | 胜平负 + 让球盘 + 大小球 + 波胆 |
| V2.0 | 滚球（Live） | 比赛进行中实时下注（玩法同上 + 滚球特有玩法） |

后期考虑套壳 APP（PWA 方案可行）。

## 四、数据接入

### 4.1 数据源
- **唯一数据源**：https://odds-api.io/v3
- **API Key**：已有（免费计划 200次/小时）
- **博彩公司**：Bet365 + Sbobet（免费计划支持）
- **无需额外比分数据源**：odds-api.io 的 events 数据包含 `scores` 字段（含全场比分+半场比分）

### 4.2 V1.0 选用玩法（4种）

| # | 市场类型 | 中文名 | 数据格式 | 结算依据 |
|---|----------|--------|----------|----------|
| 1 | ML (Money Line) | 胜平负 | `{home, draw, away}` 三个赔率 | 全场胜负结果 |
| 2 | Spread | 让球盘 | `{hdp, home, away}` 含盘口 | 让球后胜负 |
| 3 | Totals | 大小球 | `{hdp, over, under}` 含阈值 | 总进球 vs 阈值 |
| 4 | Correct Score | 波胆 | `[{label: "2-1", odds: "17.00"}, ...]` 约27个比分选项 | 精确比分匹配 |

### 4.3 波胆（Correct Score）数据结构说明

```json
// Bet365 Correct Score 市场（约27个比分）
[
  {"label": "2-1", "odds": "17.000"},    // 主2:客1
  {"label": "3-2", "odds": "34.000"},    // 主3:客2
  {"label": "5-1", "odds": "201.000"},   // 主5:客1
  {"label": "0-0", "odds": "15.000"},    // 0:0
  {"label": "1-1", "odds": "8.000"},     // 1:1
  ...
]
```

- `label` = "主队进球-客队进球"（如 "2-1" 表示主队进2球、客队进1球）
- `odds` = 该精确比分对应的赔率
- 无 over/under 结构，就是单一赔率
- 用户选择的是具体比分，而非"大于/小于"

### 4.4 API 调用规划（200次/小时限制，V1.0）

每小时 200 次请求预算分配：

| 操作 | 频率 | 消耗 |
|------|------|------|
| 获取五大联赛+世界杯赛事列表 | 每30分钟 | 6次/次 × 2 = 12次/小时 |
| 获取各赛事赔率（Bet365+Sbobet） | 每10分钟 | ~30场 × 2次 = 60次/小时 |
| 检查已结算比赛比分 | 每15分钟 | 3次 × 4 = 12次/小时 |
| **估算总计** | | **~84次/小时** |

> V1.0 赛前下注足够。V2.0 滚球需高频刷新，必须先上付费计划。

## 七、模拟下注

### 7.1 下注规则

| 项目 | 规则 |
|------|------|
| 最小下注 | 50 金币 |
| 最大下注 | 无限制（不能超过余额） |
| 串关 | 不支持（仅单关） |
| 取消下注 | 确认后不可取消 |
| 扣款时机 | 下注确认时立刻扣除金币 |
| 同一场多次下注 | **允许**。用户可对同一场比赛用不同玩法（或同一玩法多次）下多个注单 |

### 7.2 下注流程

```
用户选择比赛
→ 选择玩法（胜平负/让球盘/大小球/波胆）
→ 根据玩法选择具体选项：
    胜平负：主胜 / 平局 / 客胜（3选1）
    让球盘：主队赢盘 / 客队赢盘（2选1，盘口由API决定）
    大小球：大球 / 小球（2选1，阈值由API决定）
    波胆：从27个比分中选1个具体比分
→ 输入金币数 ≥ 50
→ 系统显示：投注金额 + 赔率 + 潜在奖励（投注额 × 赔率）
→ 用户确认 → 立即扣金币 → 生成下注记录
```

### 7.3 玩法详细说明

#### ① 胜平负（ML）
| 选项 | 说明 | 赔率来源 |
|------|------|----------|
| 主胜 | 主队获胜 | `odds.home` |
| 平局 | 双方打平 | `odds.draw` |
| 客胜 | 客队获胜 | `odds.away` |

#### ② 让球盘（Spread）
| 选项 | 说明 |
|------|------|
| 主队赢盘 | 主队实际比分 + 盘口 后仍领先 |
| 客队赢盘 | 客队实际比分 + 盘口 后领先或打平 |

> 盘口值（hdp）由 API 数据决定，如 hdp=1 表示主队让1球。
> hdp 为正 = 主队让球；hdp 为负 = 客队让球。
> 前端需清晰展示："主队(-1)" 或 "客队(+1)"。

#### ③ 大小球（Totals）
| 选项 | 说明 |
|------|------|
| 大球 | 全场总进球 > 阈值 |
| 小球 | 全场总进球 < 阈值 |

> 阈值（hdp）取 API 返回的**第一条** Totals 数据。API 可能返回多个阈值（如 2.5/3.25/3.5），始终用第一条。

#### ④ 波胆（Correct Score）
| 特征 | 说明 |
|------|------|
| 选项数量 | 约27个具体比分，**仅展示赔率最低的10个** |
| 数据格式 | `{label: "主进球-客进球", odds: "赔率"}` |
| 中奖条件 | 全场最终比分**精确匹配**所选比分 |
| 赔率范围 | 约 6.00 ~ 501.00（比分越极端赔率越高） |

> 前端展示：按赔率从低到高排序，取前10个。常见比分 0:0 / 1:1 / 1:0 / 2:1 等自然排在前面。

## 八、结算系统

### 8.1 结算流程

```
系统检测比赛状态变为 settled → 获取比分
→ 系统自动计算：
    - 本场比赛有哪些用户下注（含4种玩法）
    - 每个用户下注金额、玩法、具体选项
    - 逐一判定输赢：
        胜平负：比分对比 → 主胜/平/客胜
        让球盘：含盘口计算 → 赢盘/输盘
        大小球：总进球 vs 阈值 → 大球/小球
        波胆：精确比分匹配 → 中/不中
    - 赢家赚取金币 = 下注金额 × 下注时赔率
→ 展示结算明细给超管 → 超管手动点击"确认结算"
→ 金币打入赢家账户 → 记录结算日志
→ 比赛详情页展示最终比分
```

### 8.2 各玩法结算示例

| 玩法 | 用户选择 | 最终比分 | 盘口 | 判定 | 奖励 |
|------|----------|----------|------|------|------|
| 胜平负 | 主胜 @1.65 | 3:1 | — | ✅ 赢 | 100×1.65=165 |
| 胜平负 | 平局 @4.50 | 3:1 | — | ❌ 输 | 0 |
| 让球盘 | 主队赢盘 @1.80 | 3:1 | 主-1 | ✅ 赢（3-1>1） | 100×1.80=180 |
| 让球盘 | 主队赢盘 @1.80 | 1:0 | 主-1 | ❌ 输（1-1=0，走水） | 0 |
| 大小球 | 大球 @1.85 | 3:1 | 2.5 | ✅ 赢（4>2.5） | 100×1.85=185 |
| 大小球 | 小球 @1.95 | 1:0 | 2.5 | ✅ 赢（1<2.5） | 100×1.95=195 |
| 波胆 | 2-1 @17.00 | 2:1 | — | ✅ 赢 | 100×17=1700 |
| 波胆 | 3-1 @23.00 | 2:1 | — | ❌ 输 | 0 |

### 8.3 让球盘走水（Push）处理

当让球盘为整数（如 hdp=1）且让球后比分相等时：
- 如主队让1球，最终 1:0（让球后 0:0）→ 走水
- **处理方式**：退回本金，不计输赢

> 注：hdp 为 0.25/0.75 等非整数时不产生走水。

### 8.4 大小球走水处理

当 hdp 为整数（如 2.0）且总进球恰好等于阈值时：
- 总进球 = 2，hdp = 2.0 → 走水
- **处理方式**：退回本金

> 注：hdp 为 2.5/3.25 时不会走水。

### 8.5 异常处理

| 情况 | 处理方式 |
|------|----------|
| 比赛延期 / 中断 / 取消 | 超管选择该场比赛 → 点击"取消比赛" → 所有下注金币退回 → 记录日志 |
| 比分未更新 | 系统标记"待结算"，超管可见但无法结算 |
| 赔率数据异常（如 N/A） | 下注时后端校验，异常赔率不可下注；若已下注后才发现，退回本金 |

### 8.6 结算通知
- 不发送站内消息/推送通知
- 用户在比赛详情页直接查看比分展示
